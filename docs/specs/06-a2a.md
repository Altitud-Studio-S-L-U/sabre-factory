# 06 · Bidirectional A2A

## Outcome
Connect external agents and expose SABRE as an A2A agent in addition to MCP. Use a pinned, compatible official SDK and its published protocol contracts; verify support and license before adding the dependency.

## Interfaces and behavior
Register and review Agent Cards, supported capabilities and authentication references. Outbound delegation binds a remote task/context ID to one local step attempt with durable receipts. Polling is the baseline recovery path; use streaming when advertised. Unknown effects require reconciliation before retry. Preserve remote status, artifacts and requests for input through typed adapters.

Inbound tasks use SABRE's application authorization, quotas and work admission. Translate supported operations into existing submit/query/answer/cancel services. Discovery never authorizes execution. Treat remote data as untrusted. Expose locally by default; do not provision public ingress. Do not promise identical pause semantics for remote agents that cannot pause.

Authentication establishes the caller principal independently of message content. The owner authenticates through the supported local login or configured MCP client authorization. Agent Cards, sender fields, prompts and a Supervisor recommendation never establish owner identity. Registered external agents use separately scoped delegated identities, not the local owner bridge credential. Bind grants to permitted projects, operations and expiry; recheck revocation before effects. The existing local stdio bridge is explicitly owner-equivalent and must not be used as the public/delegated-agent ingress.

Supervisor tool calls retain the originating authenticated principal and its grant. Run selection/creation, querying and controls use those permissions and existing receipts. Permission/budget/scope increases and publication require a sufficiently authorized command; conversation alone cannot approve them. Preserve a chain of principal, delegation, operator message, proposed action, command and outcome without logging secret credentials. Reject forged owner claims, cross-project delegation and approval replay across candidates/revisions.

## Acceptance
Interoperate with a separate SDK-based test agent in both directions. Cover denied capabilities, repeated requests, lost responses, restart, cancellation, expired credentials and input-required states. Remote cost stays unknown without reliable usage evidence. Test unsupported protocol versions explicitly.
